### Method

- Timed with [hyperfine](https://github.com/sharkdp/hyperfine). **Warm**: 1 warm-up run(s), then the runs above (adaptive: at least 3, at most 10, stopping at about 3 s of timing; a command whose first run, the one that saved its output, took 5 s or more is timed by that run alone and shows 1 in the Runs column), files in the OS page cache. **Cold**: not run here. It needs a passwordless `sudo purge` (macOS) or `drop_caches` (Linux); see the header of `bench/run.sh`. Run `sudo -v` first to get cold numbers.
- Every command runs from the corpus folder, through a shell, and its exit status is ignored (grep and lwk exit 1 for "nothing found"). The start-up jobs run without a shell (`hyperfine -N`).
- Each command's output was saved once to count **Results**, **Bytes** and **≈Tokens** (bytes ÷ 4). **Noise** is the number of hits under `node_modules`, `dist`, `.git`, `vendor`, `.next`, `coverage` or `target`.
- lwk caps its answers (by default and by a hard maximum), as it is meant to for an agent; the others print everything. Result counts and sizes therefore differ by design, and the time lwk takes includes stopping early where it can.
- Text search is case-insensitive for every tool (lwk's default), so the commands carry `-i`.

No app is answering, so `lwk` is the in-process path: its file list comes from the on-disk cache when warm, and `lwk-nocache` shows the full walk (see the cache note in the summary). With the app's warm index the same query skips the walk too.
